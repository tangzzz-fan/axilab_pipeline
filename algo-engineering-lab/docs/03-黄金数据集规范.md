# 03 · 黄金数据集规范

版本：0.1.0 · 日期：2026-07-28 · 作者：lab · 状态：草稿

> golden 是真值。只允许由 Python 原型生成；禁止从 C/Swift 反向「修正」golden。

---

## 1. 生成流程

1. 入口：`uv run python -m python.generate_golden`（各 case 子命令或模块，随实现补齐）。
2. **固定随机种子**（默认 `seed=42`），写入每条记录的 `meta.seed`。
3. Python 依赖以 `uv.lock` 锁定；升级依赖后必须重生 golden 并独立提交说明。
4. 生成物写入 `golden/<case_id>/*.json`。

---

## 2. 数据格式约定（JSON）

每条记录至少包含：

```json
{
  "id": "hrv_td_001",
  "case": "hrv_time_domain",
  "category": "normal | boundary | pathological",
  "pathology": "none | missing_beat | ectopic | empty | single | extreme_noise | null",
  "input": { "rr_ms": [800.0, 810.0] },
  "expected": { "sdnn_ms": 0.0, "rmssd_ms": 0.0, "pnn50": 0.0 },
  "snapshots": {},
  "meta": {
    "seed": 42,
    "generator": "python/hrv_prototype.py",
    "source": "synthetic | physionet:<dataset>",
    "license_note": "synthetic internal"
  }
}
```

- `snapshots`：频域等长链路 case 使用；时域可为 `{}`。
- 公开数据（PhysioNet 等）必须写 `source` 与 `license_note`。

## 4. 冻结与版本化

- golden 变更必须**独立提交**，说明原因；不得与实现改动混 commit（说明书工程纪律）。
- 禁止用 C/Swift 输出覆盖 expected。
- golden 变更后，`docs/05` 历史性能数字作废重测。

---

## 5. 复现 DoD

删除 `golden/` 后按脚本重跑，产出应与版本库**逐字节一致**（或 JSON 规范排序后一致——若采用排序，须在本规范冻结「canonical JSON」规则）。当前约定：生成器写出 **sorted keys + 固定浮点格式**（`%.9g`），保证稳定。
